### DB tooling
Added npm scripts and supporting infrastructure for day-to-day DB work:

| Script | What it does |
|---|---|
| `migrate:dev` | `prisma migrate dev` |
| `migrate:reset` | `prisma migrate reset` |
| `migrate:new` | create a migration file without applying it |
| `migrate:status` | show applied/pending migrations |
| `migrate:rollback` | mark last migration as rolled back in Prisma's tracking table |

`prisma/scripts/rollback.ts` — queries `_prisma_migrations` for the last applied
migration and calls `prisma migrate resolve --rolled-back`. Includes inline
documentation on Prisma's forward-only philosophy and how to actually reverse
schema changes with manual down SQL.

Fixed `prisma/seed.ts` missing `import "dotenv/config"` — seed was failing when
run standalone outside Docker because `DATABASE_URL` wasn't loaded.

### Production-readiness fixes (scalability)

**1. Piston request timeout**
Added `AbortSignal.timeout(10_000)` to the Piston `fetch` call. A slow or
crashed Piston container would previously hang the Node process indefinitely.

**2. CORS**
`cors({ origin: CORS_ORIGIN })` mounted as first middleware. `CORS_ORIGIN`
validated by Zod at startup with `http://localhost:3000` default. Previously
there was no CORS policy at all.

**3. Pagination on problem list endpoints**
`getAllProblems` and `queryProblems` now accept `?page=&limit=` (defaults 1/20,
max 100). Repository runs `findMany` + `count` in parallel via `Promise.all`.
Response shape:

```json
{
  "status": "success",
  "data": [...],
  "pagination": { "page": 1, "limit": 20, "total": 142, "totalPages": 8 }
}
```

`PaginationSchema`, `PaginationParams`, `PaginatedResult<T>` added to
`shared/types/common.types.ts` — reusable across any future list endpoint.
